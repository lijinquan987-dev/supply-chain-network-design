# 方法论详解（Methodology）

> 本文档解释「仓网规划与优化建模」研究的方法论：从业务问题到数学模型，再到求解与验证。

## 1. 研究范式：AS-IS / TO-BE（现状 → 目标）

沿「现状 → 目标 → 差距 → 根因 → 对策」的问题解决路径：

| 步骤 | 内容 | 本项目对应 |
|---|---|---|
| 现状（AS-IS） | 单仓发全国的成本、时效瓶颈 | 梳理既有分仓实践与痛点 |
| 目标（TO-BE） | 多仓分区域后的成本—时效最优 | 求解不同 P 值下的最优仓网 |
| 差距 | 现状与目标之间的量化缺口 | 边际成本 vs 时效收益曲线 |
| 根因 | 仓数不足导致干线过长、末端覆盖差 | P-中值模型定位结构性问题 |
| 对策 | 确定仓数、仓址、覆盖分配 | 模型输出的选址与分配方案 |

## 2. 选址模型：P-中值（P-Median）

P-中值是设施选址（Facility Location）的经典模型：在候选集中选定 **P** 个设施，使所有需求点到其最近设施的**加权距离（成本）之和最小**。

### 为什么选 P-中值（而非其他模型）

| 模型 | 目标 | 本项目适用性 |
|---|---|---|
| P-中值（P-Median） | 加权运输成本最小 | ✅ 主模型：匹配「成本最优」诉求 |
| 覆盖模型（Covering） | 服务半径内覆盖最多需求 | ⚠️ 辅助：评估时效覆盖 |
| P-中心（P-Center） | 最远距离最小 | ❌ 追求极值时用，非成本导向 |
| 混合整数规划（MIP）扩展 | 加容量/时效/固定成本约束 | ✅ 本项目做了扩展 |

### 模型输入（Inputs）

- **需求点（Demand Points）**：337 个地级行政区，权重 = 需求量（如件量/吨位占比）
- **候选仓（Candidate Sites）**：15 个候选城市（基于城市群与交通骨架预筛）
- **距离/成本矩阵（Cost Matrix）**：高德 API 实测城间驾车距离与耗时

### 目标与约束（Objective & Constraints）

见 `README.md` 中的数学表达。要点：

1. **每个需求点恰好被一个仓覆盖**（单一归属，便于运营管理）
2. **只能分配给已开设的仓**（逻辑一致性）
3. **恰好开设 P 个仓**（回答「几个仓」）
4. **容量约束（可选）**：仓的可服务量上限
5. **时效约束（扩展）**：指定城市分级时效目标、整体次日达达成率下限

## 3. 空间骨架：城市群 + 交通骨架

先定格局再定细节——以「4 极 8 组群 9 组团」的空间分层（Tier-1/2/3 城市圈层）约束候选仓范围，避免纯数学解脱离现实（如把仓选在无人区）：

- **4 极**：京津冀、长三角、粤港澳、成渝（国家极核）
- **8 组群**：山东半岛、中原、关中、辽中南、哈长、北部湾、滇中、黔中等城市群
- **9 组团**：次一级城市组团

这一分层同时服务于**分级时效**：核心城市群内次日达、外围组团按需分级。

## 4. 数据获取（Data Acquisition）

- 高德开放平台 API（AMap API）地理编码：337 地级行政区 → 经纬度
- 高德距离测量 API：城间驾车距离（km）与耗时（min）
- 限速策略（Rate Limit）：批量请求间隔 0.2–0.3s，防触发风控

## 5. 求解与验证（Solve & Verify）

- **双轨求解**：Excel + OpenSolver（业务侧习惯，可审计）↔ Python + CBC（本仓，可复现）
- **交叉验证**：两套求解器对同一问题输出应一致，保证结果可信
- **敏感性分析（后续）**：P 从 1→15 全枚举，输出边际成本曲线与时效达成率曲线

## 6. 结果解读（Interpretation）

- **比选表**：不同 P 值下的总成本（仓储 + 补货 + 配送）与次日达达成率
- **覆盖图**：仓址 + 覆盖范围 + 时效分级（升级动作③）
- **边际分析**：每增加一个仓，多花的钱（边际成本）换来的时效提升（边际收益）是否划算——直接支撑业务决策
